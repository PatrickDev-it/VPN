## 1. mitmproxy — Authenticated Ingress

**Base image:** `python:3.12-slim` (built from root `Dockerfile`)
**Exposed port:** `${MITMPROXY_BIND_IP:-0.0.0.0}:${MITMPROXY_BIND_PORT:-8080}:8080`
**Dependencies:** `privoxy`, `unbound`

**Startup command:**
```
mitmdump \
  --listen-host 0.0.0.0 \
  --listen-port 8080 \
  --mode upstream:http://privoxy:8118 \
  --set connection_strategy=lazy \
  -s app/gatekeeper.py
```

**Environment variables read at runtime:**

| Variable | Default | Description |
|----------|---------|-------------|
| `AUTH_MODE` | `basic` | Authentication mode: `basic` or `token` |
| `USERS_FILE` | `/app/app/users.yaml` | Path to user credentials file |
| `POLICY_FILE` | `/app/app/policy.yaml` | Path to policy rules file |
| `RATE_LIMIT_RPM` | `120` | Max requests per minute per user |
| `RATE_LIMIT_WINDOW_SEC` | `60` | Sliding window duration in seconds |
| `AUTH_LOG_FILE` | `/app/logs/auth.log` | Authentication event log path |
| `TRAFFIC_LOG_FILE` | `/app/logs/traffic.log` | Traffic log path |

**Docker security:**
- `security_opt: no-new-privileges:true`
- `cap_drop: ALL`
- Runtime user: `appuser` (unprivileged, created in Dockerfile)

**Python addon:** `app/gatekeeper.py`
See [gatekeeper.md](gatekeeper.md) for the complete hook-by-hook documentation.

**Mounted volumes:**
- `./app` → `/app/app` (read-only) — policy, users, gatekeeper source
- `./cron` → `/app/cron` (read-only) — blacklist update script
- `./unbound` → `/app/unbound` — blacklist.conf (writable, updated by cron)
- `./logs` → `/app/logs` — auth.log and traffic.log

## 2. Privoxy — HTTP Forward Proxy

**Base image:** `debian:12-slim` with `privoxy` package (built from `services/privoxy/Dockerfile`)
**Exposed port:** `${PRIVOXY_BIND_IP:-127.0.0.1}:${PRIVOXY_BIND_PORT:-8118}:8118`
**Dependencies:** `tor`

**Docker security:**
- `security_opt: no-new-privileges:true`
- `cap_drop: ALL`

**Configuration** (`privoxy/config`, generated by `bootstrap.sh` from `.env`):
```
listen-address          0.0.0.0:8118
forward-socks5t   /     tor:9050   .
socket-timeout          300
forwarded-connect-retries 1
max-client-connections  1024
keep-alive-timeout      5
tolerate-pipelining     1
```

**Key parameters:**

| Parameter | Value | Purpose |
|-----------|-------|---------|
| `listen-address` | `0.0.0.0:8118` | Accept mitmproxy traffic on the isolated Compose network |
| `forward-socks5t` | `/ tor:9050 .` | Forward all traffic via SOCKS5 to the Tor container; `.` disables direct connections |
| `socket-timeout` | `300` | Connection timeout in seconds — set high to tolerate Tor latency |
| `max-client-connections` | `1024` | Maximum simultaneous client connections |
| `tolerate-pipelining` | `1` | Accept pipelined requests from mitmproxy |

> **Note:** Privoxy's built-in content filtering is not used in this stack.
> It acts solely as an HTTP→SOCKS5 translation layer.
> Its container listener is network-wide, while the published host port remains restricted to `127.0.0.1`.

**Environment variables:**
- `TOR_SOCKS_HOST` (default: `tor`) — Tor container hostname on `proxy_net`
- `TOR_SOCKS_PORT` (default: `9050`) — Tor SOCKS port

## 3. Tor — Anonymization Layer

**Base image:** `debian:12-slim` with `tor` package (built from `services/tor/Dockerfile`)
**Exposed port:** none — internal `proxy_net` only
**Runtime user:** `debian-tor` (unprivileged)

**Docker security:**
- `security_opt: no-new-privileges:true`
- `cap_drop: ALL`

**Configuration** (`tor/torrc`):

### Entry Guards
```
UseEntryGuards 1
NumEntryGuards 2
```
Persistent entry guards reduce exposure to guard–exit correlation attacks (Sybil-style timing attacks).

### Geo-Constrained Exit Policy
```
ExitNodes     {de},{it},{ad},{mc},{al},{mm},{mv},{vn},{uz}
ExcludeNodes  {ch},{us},{gb},{au},{ca},{fr},{nl},{be},{ie},{se},{no},{dk},{fi},{jp},{kr},{cn},{ru}
StrictNodes 1
```

**Allowed exits:** Germany, Italy, Andorra, Monaco, Albania, Myanmar, Maldives, Vietnam, Uzbekistan.

**Excluded exits (rationale):**
- 5-Eyes members: US, GB, AU, CA
- 9-Eyes / 14-Eyes extensions: FR, NL, BE, IE, SE, NO, DK, FI, DE (partially)
- Mandatory data-retention legislation: CH, SE, NO, DK, FI
- Internet censorship / surveillance: CN, RU
- High ad-market CPM: JP, KR

`StrictNodes 1` means Tor will fail to build a circuit rather than use a non-approved exit.
This is a deliberate privacy-over-availability trade-off — do not remove without discussion.

### Circuit Tuning (Anti-Profiling)
```
NewCircuitPeriod 300        # new circuit every 5 minutes
MaxCircuitDirtiness 1800    # circuit retired after 30 minutes
CircuitBuildTimeout 30
MaxClientCircuitsPending 100
```
Frequent circuit rotation prevents traffic correlation across requests.

### Traffic Padding
```
ConnectionPadding 1         # add dummy Tor cells to obscure traffic patterns
ReducedConnectionPadding 0  # full padding (not reduced)
EnforceDistinctSubnets 1
```

### Stream Isolation
```
SocksPort 9050 IsolateDestAddr IsolateDestPort IsolateSOCKSAuth
```
Separate circuits per destination IP, destination port, and SOCKS credential.
This prevents cross-request correlation even within the same user session.

### Base Settings
```
ClientOnly 1          # client-only mode, no relay participation
SafeSocks 1           # reject non-anonymous SOCKS4 connections
DNSPort 0             # Tor DNS not exposed (Unbound handles DNS)
AutomapHostsOnResolve 0
```

**Logs (inside the container):**
- `/var/log/tor/notices.log` — important events (circuit built, guard changed)
- `/var/log/tor/info.log` — detailed circuit and connection info

## 4. Unbound — DNS Resolver

**Base image:** `debian:12-slim` with `unbound` package (built from `services/unbound/Dockerfile`)
**Exposed ports:**
- `${UNBOUND_BIND_IP:-127.0.0.1}:${UNBOUND_DNS_PORT:-5353}:53/tcp+udp` — standard DNS
- `${UNBOUND_DOT_BIND_IP:-127.0.0.1}:${UNBOUND_DOT_PORT:-853}:853/tcp` — DNS-over-TLS

**Docker security:**
- `security_opt: no-new-privileges:true`
- `cap_add: NET_BIND_SERVICE` (required for binding port 53)
- Runtime user: `unbound` (unprivileged)

**Configuration** (`unbound/unbound.conf`):

Runtime diagnostics are written to container stdout/stderr (`use-syslog: no`) so fatal startup errors and
resolver warnings remain available through `docker compose logs unbound` without a sidecar syslog daemon.

### Performance Tuning (4-core / 4 GB RAM baseline)
```
num-threads: 4
msg-cache-slabs: 4         # power-of-2 near num-threads reduces lock contention
rrset-cache-slabs: 4
msg-cache-size: 128m
rrset-cache-size: 512m
key-cache-size: 64m
neg-cache-size: 32m
so-rcvbuf: 2m
so-sndbuf: 2m
outgoing-range: 4096
```

### DNSSEC Validation
```
auto-trust-anchor-file: "/var/lib/unbound/root.key"
val-permissive-mode: no      # DNSSEC enforced — unsigned responses are rejected
module-config: "validator iterator"
```

### DNS Privacy
```
hide-identity: yes
hide-version: yes
qname-minimisation: yes      # send only the necessary query portion to upstream
use-caps-for-id: yes         # 0x20 encoding against DNS cache poisoning
harden-glue: yes
harden-dnssec-stripped: yes
harden-below-nxdomain: yes
harden-referral-path: yes
harden-algo-downgrade: yes
```

### DNS-over-TLS (DoT)
```
tls-service-key: "/etc/nginx/ssl-certificates/server.key"
tls-service-pem: "/etc/nginx/ssl-certificates/server.crt"
```
Placeholders `{{TLS_SERVICE_KEY}}` and `{{TLS_SERVICE_PEM}}` are replaced by `bootstrap.sh`
based on `TLS_MODE` at stack startup.

### Ad/Tracker Sinkhole
```
include: "/etc/unbound/blacklist.conf"
```
`blacklist.conf` is auto-generated every 6 hours by `cron/update_blacklist.sh` from the
[StevenBlack/hosts](https://github.com/StevenBlack/hosts) blocklist.
Format: `local-zone: "domain.com" always_nxdomain`

### Remote Control Interface
```
remote-control:
    control-enable: yes
    control-interface: 127.0.0.1
    control-port: 8953
    control-use-cert: no
```
Enables `unbound-control` for statistics and cache management without a container restart.
The interface is restricted to the container loopback namespace, so the local control channel does not
depend on generated TLS credentials and is not reachable from the host or Compose network.

**Exposing DoT publicly (optional):**
To make the DNS-over-TLS resolver accessible to external clients, set in `.env`:
```
UNBOUND_BIND_IP=0.0.0.0
UNBOUND_DOT_BIND_IP=0.0.0.0
```
Then open port 853/tcp in UFW. Review [security.md](security.md) — open resolvers can be abused.

## Service Interaction Map

```
Client :8080 → mitmproxy → (HTTP upstream) → privoxy:8118 → (SOCKS5) → tor:9050
mitmproxy  → socket.gethostbyname() → host DNS resolver (Unbound if configured)
Client DoT → unbound:853
```

> **DNS resolution note:** `is_dns_blocked()` in `gatekeeper.py` calls `socket.gethostbyname()`,
> which uses the container's system DNS resolver. For the Unbound sinkhole to take effect,
> the mitmproxy container must use Unbound as its DNS resolver. This is automatic if the Docker
> daemon is configured with `--dns` pointing to the Unbound container, or via host-level
> `/etc/resolv.conf` configuration on the VPS.
